4. RECOMMENDED 5-MINUTE EVALUATION WALKTHROUGH
================================================================================

SCENARIO 1: Renting a Book with Escrow Protection
1. Log in as Student Buyer (user@bookwagon.com / 123456789).
2. Browse catalog at http://localhost/BookwagonNew1/rentbooks.php
3. Select a book (e.g. "Clean Code" or "Atomic Habits") and click "Rent Now".
4. Choose duration (e.g. 2 weeks) and confirm.
5. The system automatically places the rental fee and the refundable security
   deposit into platform escrow.

SCENARIO 2: Dual-Party QR Handover & Non-Repudiation
1. Log in as Seller (seller@bookwagon.com / 123456789) in another browser/tab.
2. Go to Seller Dashboard -> Rented Books (http://localhost/BookwagonNew1/rented_books.php).
3. Under the active rental, click "Handover".
4. Upload a baseline meetup condition photo and display the dynamic QR Code.
5. On the Buyer side, confirm condition and scan/verify the QR code.
   The transaction timestamp locks, eliminating pre-existing damage arguments.

SCENARIO 3: Return Approval & Automated Deposit Refund
1. When the rental period concludes, the seller inspects the book.
2. If undamaged, seller clicks "Approve Return".
3. The system automatically refunds 100% of the security deposit back to the 
   buyer's wallet, and releases rental earnings to the seller.

SCENARIO 4: Damage Dispute & Administrative Photo Arbitration
1. If the book is returned damaged, the seller files a damage claim with a photo.
2. Log in as Admin (admin / 123456789) and visit:
   http://localhost/BookwagonNew1/Admin/admin_disputes.php
3. Admin compares the Pre-Handover Photo vs. Post-Return Photo side-by-side
   and issues a binding resolution (Full Refund, Partial Deduction, or Forfeit).

SCENARIO 5: Autonomous Database Intrusion Detection Triggers
1. Open Admin Portal (http://localhost/BookwagonNew1/Admin/) and view dashboard.
2. Open phpMyAdmin and tamper directly with a user's wallet balance:
   UPDATE users SET wallet_balance = 999999.00 WHERE id = 2;
3. Refresh the Admin Dashboard: The autonomous MariaDB trigger immediately flags 
   the unauthorized change with a RED "RISK: DIRECT_WALLET_TAMPERING" banner.
4. Click "SOLVE", enter incident notes, and resolve the threat.
